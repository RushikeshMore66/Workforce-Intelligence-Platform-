# Case Study 01 — Product Intent and Industrial Problem

## Goal

Understand why the platform exists before learning its code.

## Real problem

A company can have people working every day while management still lacks a reliable current picture of work.

The data exists, but it is scattered.

## Product response

WIP creates a structured execution system where:

`Person -> Work -> Status -> Update -> Event -> Operational View`

## Case study

Imagine a 30-person automation company.

Today:

- engineer sends WhatsApp update
- site technician calls supervisor
- material problem is discussed in a meeting
- owner asks for status at 7 PM
- supervisor manually creates a summary

With WIP:

- job/project exists
- tasks exist
- each task has an owner
- worker updates status
- on-hold reason is recorded
- transition is auditable
- progress is derived
- supervisor sees the current state

## Why this is important

We are not digitizing "employees."

We are digitizing **the movement of work through people**.

## What I should be able to explain

> "The platform solves operational visibility and accountability problems by turning work execution into structured data."

## Key terms

## Industrial customization

The stable engine is the same.

Only the work vocabulary changes.

| Industry | Project/Job | Example task |
|---|---|---|
| Software agency | Client project | Build API |
| Automation agency | Automation job | Commission PLC |
| Manufacturing | Production/job order | Machine component |
| Materials business | Supply/job | Prepare dispatch |
| Construction | Site project | Install electrical work |
| Field service | Service job | Repair machine |
